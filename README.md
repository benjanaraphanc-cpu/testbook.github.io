## ขั้นตอนที่ 2: สร้างฐานข้อมูล MySQL

ไฟล์ SQL อยู่ที่ `database/schema.sql` สร้างฐานข้อมูล `ku_car_booking` และ 3 ตาราง:

| ตาราง | หน้าที่ |
|---|---|
| `users` | ผู้ใช้งาน มีคอลัมน์ `role` = `user` (ผู้จอง) หรือ `admin` (ผู้ดูแลระบบ) |
| `cars` | ข้อมูลรถ: ทะเบียน ยี่ห้อ รุ่น ประเภท จำนวนที่นั่ง รูปภาพ สถานะ |
| `bookings` | รายการจอง: รถ ผู้จอง ช่วงเวลา จุดรับ จุดส่ง วัตถุประสงค์ สถานะ (`pending` / `approved` / `rejected` / `cancelled`) |

เลือกวิธีใดวิธีหนึ่ง:

**วิธี A — ใช้คำสั่งของโปรเจกต์ (แนะนำ)** : ทำหลังจากทำขั้นตอนที่ 5 ข้อ 1-3 (เปิดโปรเจกต์ + `npm install` + สร้าง `.env`)
```bash
npm run db:init
```

**วิธี B — ใช้ phpMyAdmin**
1. เปิด http://localhost/phpmyadmin
2. แท็บ **SQL** → เปิดไฟล์ `database/schema.sql` คัดลอกทั้งหมดมาวาง → กด **ดำเนินการ**

> ⚠️ สคริปต์จะ `DROP TABLE` แล้วสร้างใหม่ — รันซ้ำจะล้างข้อมูลเดิมทั้งหมด

**บัญชีตัวอย่าง** (สร้างอัตโนมัติ "ครั้งแรกที่เปิดเซิร์ฟเวอร์" เมื่อตาราง `users` ยังว่าง):

| ผู้ดูแลระบบ (Admin) | `admin` | `admin1234` |

## ขั้นตอนที่ 4: ภาพรวมโค้ดและกลไกสำคัญ

### 4.1 การแบ่งสิทธิ์ (Authentication & Authorization)
- ล็อกอินแล้วเก็บข้อมูลผู้ใช้ไว้ใน **session** (คุกกี้ `ku.sid` แบบ httpOnly) — รหัสผ่านเก็บเป็น bcrypt hash
- `middleware/auth.js` มี 3 ตัวกรอง:
  - `requireLogin` — ต้องล็อกอิน
  - `requireUser` — ต้องเป็น `role = user` (ใช้กับหน้าจอง/ประวัติการจอง/ส่งคำขอจอง; admin จะถูกส่งไป `/admin`)
  - `requireAdmin` — ต้องเป็น `role = admin` (ใช้กับ `/admin` และ `/api/admin/*` ทั้งหมด)
- ผู้ใช้ทั่วไปเปิด `/admin` → ได้หน้า **403**; เรียก `/api/admin/*` → ได้ JSON **403** ไม่มีทางเข้าถึงข้อมูลได้
- การสมัครสมาชิกผ่านหน้าเว็บสร้างได้เฉพาะ `role = user` เท่านั้น (ฝั่งเซิร์ฟเวอร์ fix ค่าไว้ ไม่รับ role จาก client)
- Admin ทำได้เฉพาะ "อนุมัติ / ไม่อนุมัติ" (API ส่งคำขอจองถูกกันไว้เฉพาะ `user`)

### 4.2 การป้องกันการจองซ้ำ (`services/bookingService.js`)
เงื่อนไขทับซ้อนเวลาของรถคันเดียวกัน:
```sql
SELECT id FROM bookings
 WHERE car_id = ?
   AND status IN ('pending','approved')   -- ที่ถูกจองไว้ หรือ อนุมัติแล้ว
   AND start_datetime < :เวลาสิ้นสุดใหม่
   AND end_datetime   > :เวลาเริ่มต้นใหม่
```
- ถ้าพบ → **ไม่บันทึก** และตอบ HTTP **409** พร้อมข้อความระบุช่วงเวลาที่ชน → หน้าเว็บแสดงแจ้งเตือนทันที
- จองต่อกันพอดี (เดิมจบ 12:00 ใหม่เริ่ม 12:00) ถือว่าไม่ซ้ำ
- การจองที่ `rejected` หรือ `cancelled` จะคืนช่วงเวลาให้จองใหม่ได้
- การสร้างการจองทำใน **transaction** และล็อกแถวรถด้วย `SELECT ... FOR UPDATE` กันกรณีสองคนกดจองรถคันเดียวกันพร้อมกัน
- ตอน Admin กด "อนุมัติ" จะตรวจซ้ำอีกชั้น
- หน้าจองเรียก `/api/bookings/check` ให้แจ้งเตือนทันทีที่เลือกวัน-เวลา ก่อนกดส่ง

### 4.3 หน้าจอ
- **`/` ปฏิทินผู้จอง** — FullCalendar แสดงการจองที่มีอยู่แล้ว (เขียว = อนุมัติแล้ว, เหลือง = รออนุมัติ, ขอบทอง = ของฉัน) กรองตามรถได้ คลิกวันที่เพื่อไปหน้าจองในวันนั้น
- **`/book` จองรถ** — เลือกรถจากการ์ดที่มี **รูปรถ + ทะเบียน** กรอก **จุดหมายรับ / จุดหมายส่ง** (มีกล่องสรุปแสดงรูป ทะเบียน จุดรับ จุดส่งแบบเรียลไทม์) พร้อมแสดงช่วงเวลาที่รถคันนั้นถูกจองแล้ว
- **`/my-bookings`** — ติดตามสถานะ ดูหมายเหตุจาก Admin และยกเลิกการจองที่ยังไม่เริ่มได้
- **`/admin`** — การ์ดสรุปจำนวน ตารางรายการจองทั้งหมด (กรองตามสถานะ) ปุ่มอนุมัติ / ไม่อนุมัติ พร้อมช่องหมายเหตุ

### 4.4 ความปลอดภัยที่ทำไว้แล้ว
SQL ใช้ parameterized query (`?`) ทุกจุด · escape ข้อความก่อนแสดงผล (กัน XSS) · bcrypt · regenerate session ตอนล็อกอิน · จำกัดการเดารหัสผ่าน (ผิดเกิน 8 ครั้ง/15 นาที) · ตรวจสิทธิ์ทุกเส้นทางที่ฝั่งเซิร์ฟเวอร์

## ขั้นตอนที่ 5: เปิดโปรเจกต์ รันเซิร์ฟเวอร์ และทดสอบ

### 5.1 รันโปรเจกต์
1. แตกไฟล์ zip → เปิด VS Code → **File > Open Folder…** → เลือกโฟลเดอร์ `ku-car-booking`
2. เปิด Terminal ใน VS Code: เมนู **Terminal > New Terminal** (หรือ `` Ctrl+` ``)
3. สร้างไฟล์ตั้งค่า:
   ```bash
   # Windows (Command Prompt / PowerShell)
   copy .env.example .env
   # macOS / Linux
   cp .env.example .env
   ```
   เปิด `.env` แก้ `DB_PASSWORD` ถ้า MySQL ของคุณมีรหัสผ่าน (XAMPP ปล่อยว่าง) และเปลี่ยน `SESSION_SECRET` เป็นข้อความสุ่มของคุณเอง
4. ติดตั้งไลบรารี:
   ```bash
   npm install
   ```
5. สร้างฐานข้อมูล (ต้องเปิด MySQL อยู่):
   ```bash
   npm run db:init
   ```
6. เริ่มเซิร์ฟเวอร์:
   ```bash
   npm start
   ```
   ถ้าสำเร็จจะเห็น
   ```
   สร้างบัญชีตัวอย่างแล้ว -> admin / admin1234  และ  user / user1234
   ✅ ระบบจองรถ ม.เกษตรศาสตร์ พร้อมใช้งานที่ http://localhost:3000
   ```
7. เปิดเบราว์เซอร์ไปที่ **http://localhost:3000**  
   (ระหว่างแก้โค้ดใช้ `npm run dev` เพื่อให้เซิร์ฟเวอร์รีสตาร์ทอัตโนมัติเมื่อบันทึกไฟล์)

### 5.2 ทดสอบทีละสเต็ป

**A) ทดสอบฝั่งผู้จองทั่วไป**
1. ที่หน้า Login กรอก `user` / `user1234` → เข้าสู่ **ปฏิทินการจอง** เห็นรายการจองตัวอย่างบนปฏิทิน
2. ลองเลือกตัวกรองรถ (มุมขวาของปฏิทิน) → ปฏิทินแสดงเฉพาะรถคันนั้น
3. กดปุ่ม **จองรถ** → เลือกการ์ดรถ (เห็นรูป + ทะเบียน) → กล่องด้านขวาแสดงรูปรถ ทะเบียน
4. กรอกจุดหมายรับ / จุดหมายส่ง / วัน-เวลา / ผู้โดยสาร / วัตถุประสงค์ → กด **ส่งคำขอจองรถ** → ระบบพาไป **การจองของฉัน** สถานะ "รออนุมัติ"

**B) ทดสอบการป้องกันการจองซ้ำ**
1. จองรถคันเดิมในวัน-เวลาที่ทับกับรายการที่มีอยู่ (ดูจากปฏิทิน/รายการ "ช่วงเวลาที่รถถูกจองแล้ว")
2. ทันทีที่เลือกเวลา กล่องสีแดงจะแจ้งว่า **"รถคันนี้ถูกจองไว้ … กรุณาเลือกเวลาหรือรถคันอื่น"**
3. ลองกดส่งต่อ → ระบบ **ไม่บันทึก** และขึ้นแจ้งเตือนสีแดง
4. เปลี่ยนไปจองเวลาที่ต่อกันพอดี (เช่น เดิมจบ 12:00 ใหม่เริ่ม 12:00) → จองได้

**C) ทดสอบการแบ่งสิทธิ์**
1. ขณะล็อกอินเป็น `user` ลองพิมพ์ **http://localhost:3000/admin** → ต้องเห็นหน้า **403 ไม่มีสิทธิ์เข้าถึง**
2. ลองเปิด http://localhost:3000/api/admin/bookings → ได้ `{"message":"คุณไม่มีสิทธิ์เข้าถึงส่วนผู้ดูแลระบบ"}`
3. กด **ออกจากระบบ** แล้วลองเปิด `/` โดยไม่ล็อกอิน → ถูกส่งกลับ `/login`

**D) ทดสอบฝั่ง Admin**
1. ออกจากระบบ → ล็อกอิน `admin` / `admin1234` → เข้า **Admin Dashboard** อัตโนมัติ
2. แท็บ **รออนุมัติ** เห็นคำขอของผู้ใช้ → กด **อนุมัติ** → ใส่หมายเหตุ (ถ้ามี) → ยืนยัน
3. กด **ไม่อนุมัติ** อีกรายการ → ใส่เหตุผล → ยืนยัน
4. ล็อกอินกลับเป็น `user` ที่ **การจองของฉัน** → เห็นสถานะ "อนุมัติแล้ว" / "ไม่อนุมัติ" พร้อมหมายเหตุ
5. ที่ปฏิทิน การจองที่อนุมัติแล้วเป็นสีเขียว และรถช่วงนั้นจองซ้ำไม่ได้ — ส่วนรายการที่ "ไม่อนุมัติ" จะคืนช่วงเวลาให้จองใหม่ได้

### 5.3 แก้ปัญหาที่พบบ่อย
| อาการ | วิธีแก้ |
|---|---|
| `ECONNREFUSED` / เชื่อมต่อฐานข้อมูลไม่สำเร็จ | ยังไม่ได้ Start MySQL ใน XAMPP หรือ `DB_PORT` ไม่ตรง |
| `ER_ACCESS_DENIED_ERROR` | `DB_USER` / `DB_PASSWORD` ใน `.env` ไม่ถูกต้อง |
| `ER_BAD_DB_ERROR` / `Table ... doesn't exist` | ยังไม่ได้รัน `npm run db:init` |
| `EADDRINUSE` พอร์ต 3000 ถูกใช้อยู่ | เปลี่ยน `PORT=3001` ใน `.env` |
| หน้าเว็บไม่มีสไตล์/ปฏิทินไม่ขึ้น | ต้องต่ออินเทอร์เน็ต (โหลด Bootstrap/FullCalendar จาก CDN) |
| ต้องการตั้ง admin เพิ่ม | สมัครสมาชิกปกติ แล้วรัน `UPDATE users SET role='admin' WHERE username='ชื่อผู้ใช้';` |
| ต้องการเพิ่ม/แก้รถ | แก้ตาราง `cars` ใน phpMyAdmin (ใส่รูปไว้ที่ `public/images/cars/` แล้วระบุ path ในคอลัมน์ `image_url`) |

## ขั้นตอนที่ 6: ภาพหน้าจอของแต่ละหน้า

## หมายเหตุสำหรับการนำไปใช้งานจริง (Production)
- เปลี่ยนรหัสผ่านของ `admin` / `user` ตัวอย่าง และตั้ง `SESSION_SECRET` ให้ยาวและสุ่ม
- Session ในโปรเจกต์นี้เก็บในหน่วยความจำ (เหมาะกับการพัฒนา/ใช้งานขนาดเล็ก) — ถ้าใช้จริงจังควรใช้ session store ใน MySQL/Redis และเปิด HTTPS
- ควรติดตั้งหลังไฟร์วอลล์/Reverse proxy ของมหาวิทยาลัยและสำรองฐานข้อมูลสม่ำเสมอ
